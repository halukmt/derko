Galerie / Fotoalbum Optionen – Testseite xalbum_test

Vergleich verschiedener Ansätze zur Darstellung einer Apartment-Bildergalerie unter Gesichtspunkten von Performance, Barrierefreiheit, SEO und Sicherheit. Verwendete Beispielbilder stammen aus /assets/img/wohnungen/rahm/ (bereits im Projekt vorhanden).

Option 1: Reines Responsive Grid (kein Lightbox-Popup)

Minimalster Ansatz: Bilder als responsive Grid mit object-fit, Lazy Loading (native) & semantischen Alt-Texten. Vorteil: 0 Bytes zusätzliches JS; Nachteil: Kein Vollbild / Kontextwechsel. Kann mit CSS aspect-ratio layout-stabil gestaltet werden.

Option 2: Bootstrap Modal als Lightbox

Wiederverwendung des vorhandenen Bootstrap Bundles (bereits via CDN geladen). Ein einziges Modal-Element, das beim Klick das entsprechende Bild nachlädt. Vorteile: Fokus-Handling & ARIA rudimentär vorhanden; Nachteile: Kein nativer Swipe, Teil der Bootstrap-JS-Payload (~< 50KB gzip schon vorhanden), Navigation implementieren wir selbst.

Option 3: Eigene Minimal-Lightbox (kein Framework)

Ziel: Sehr kleine zusätzliche JS-Menge (< ~2 KB minifiziert denkbar), volle Kontrolle, kein externes CDN. Features: Keyboard (ESC, ←, →), Fokusfalle, Wrap-Around Navigation, Prefetch Nachbarbilder.
Nachteil: Wartung eigener Code; kein Pinch-Zoom (könnte man ergänzen).

Option 4: Externe Library (PhotoSwipe – lazy geladen)

PhotoSwipe ist eine etablierte, barrierearm designte Lightbox mit Touch/Swipe/Zoom. Strategie: Assets nur bei Bedarf laden (Button). So bleibt Initial Load schlank.
Vorteile: Zoom, Gesten, gute Accessibility, History-Integration möglich. Nachteile: Zusätzliches JS/CSS (~30–40 KB gzip), CSP muss CDN zulassen (hier via jsDelivr bereits erlaubt), Sicherheits-Updates verfolgen.

Zusammenfassung & Bewertung

Empfehlung produktiv: Beginne mit Option 3 (eigene Minimal-Lightbox) – klein, kontrolliert, passt zu aktuellem Tech-Stack. Upgrade zu Option 4 nur wenn Zoom / Swipe zwingend benötigt.

Technische Hinweise

  • Alle Bilder verwenden loading="lazy" für nicht-hero Thumbnails.
  • Alt-Texte sind generisch – produktiv spezifische Beschreibungen (z.B. „Küche – Wohnung Rahm“).
  • Option 3 prefetch’t Nachbarbilder (Performance beim Navigieren).
  • Option 4 lädt Library erst bei Nutzerintention (Button).
